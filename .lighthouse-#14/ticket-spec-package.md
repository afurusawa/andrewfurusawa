## Question

What **written artifact(s)** constitute the destination spec, and when is this map considered done?

Decide at least:

1. Where the spec lives (e.g. `docs/` design doc, a single GitHub issue PRD, ADRs for hard choices, combination).
2. Required sections the spec must contain before the map closes (so implementers are not guessing).
3. What is explicitly *not* required in the first spec (e.g. pixel-perfect comps, full copy deck, asset pack).
4. Handoff rule: what "ready to implement" means for a later non-wayfinder session.

This is about packaging and done-criteria for the **spec**, not implementing `/90s`.
